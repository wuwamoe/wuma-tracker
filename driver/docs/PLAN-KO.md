# WumaTracker 드라이버 보안 요구사항

## 목적

`PLAN-KO.md`는 `PLAN.md`의 한국어 번역입니다. 요구사항의 기준 문서는 `driver/docs/PLAN.md`이며, 이 문서는 같은 구조와 의미를 유지해야 합니다. 구현 순서, 임시 마이그레이션 상태, 코드 단위 작업은 `driver/docs/TASKS.md`에 둡니다.

최종 시스템은 WumaTracker Windows 드라이버를 단일 목적의 플레이어 위치 텔레메트리 컴포넌트로 만들어야 합니다. 이 드라이버는 범용 메모리 리더, 패턴 스캐너, 임의 포인터 체인 실행기, 권한 상승 프리미티브로 재사용될 수 없어야 합니다.

## 범위

범위 내:
- WumaTracker 좌표 읽기 경로를 위한 Windows 커널 드라이버 강화.
- 앱의 드라이버 접근을 중재하는 권한 있는 Windows 헬퍼 서비스.
- Tauri 앱과 헬퍼 서비스의 연동.
- 드라이버의 합법적 단일 목적을 설명하기 위한 제출 및 검토 자료.
- `driver/docs/` 아래 문서.

범위 외:
- WDF 마이그레이션. WDF는 장기 유지보수를 위한 미래 선택지이며 이번 강화의 요구사항은 아닙니다.
- 실제 게임 오프셋 값을 문서에 공개하는 것.
- 범용 프로세스 검사, 메모리 읽기/쓰기, 디버깅, 스캔, 안티치트 우회 기능 구현.

## 위협 모델

설계는 다음 위험을 줄여야 합니다:
- 임의 로컬 프로세스가 디바이스 객체를 직접 여는 위험.
- 변조된 Tauri 앱이 의도된 오버레이 워크플로 밖에서 드라이버를 사용하는 위험.
- 손상된 헬퍼가 드라이버를 임의 프로세스에 사용하는 위험.
- 임의 PID, 베이스 주소, 체인, 패턴 매개변수를 전달하여 드라이버를 취약 드라이버 프리미티브처럼 재사용하는 위험.
- 정적 스캐너나 수동 검토자가 바이너리를 범용 게임 치트 또는 LOLDriver 형태의 읽기 프리미티브로 분류하는 위험.
- 영구 panic loop 때문에 커널 불안정성이 숨겨지는 위험.

설계가 보장하지 않는 것:
- 완전히 손상된 커널에 대한 보호.
- 도난 또는 오발급된 서명 인증서에 대한 보호.
- 게임 업데이트로 실행 파일 이름, 모듈 레이아웃, 좌표 체인이 변경되는 상황에 대한 자동 호환성.

## 최종 아키텍처 요구사항

최종 아키텍처는 세 컴포넌트로 구성됩니다:
- **드라이버**: 하드코딩된 대상 프로세스와 하드코딩된 좌표 체인에서 현재 플레이어 월드 위치만 읽는 단일 목적 커널 컴포넌트.
- **헬퍼 서비스**: 드라이버 핸들을 소유하고 제한된 로컬 IPC 계약을 노출하는 권한 있는 서명된 Windows 서비스 또는 상승된 프로세스.
- **Tauri 앱**: 헬퍼 서비스를 통해서만 위치 데이터를 요청하는 일반 앱 프로세스.

최종 아키텍처에서 Tauri 앱은 `\\.\WumaDisplayService`를 직접 열면 안 됩니다.

## 드라이버 요구사항

최종 상태에서 드라이버는 정확히 하나의 IOCTL만 노출해야 합니다: `IOCTL_GET_LOCATION`.

드라이버는 다음을 노출하거나 유지하면 안 됩니다:
- `IOCTL_AUTH`
- `IOCTL_SET_CONFIG`
- `IOCTL_PATTERN_SEARCH`
- 세션 토큰
- 호출자가 제공하는 PID 인증
- 호출자가 제공하는 베이스 주소
- 호출자가 제공하는 포인터 체인
- 호출자가 제공하는 패턴 바이트 또는 스캔 범위
- 가변 전역 세션 설정

드라이버는 앱에서 사용하는 Windows 게임 프로세스 이름과 동일한 `Client-Win64-Shipping.exe`를 대상 프로세스 이름으로 하드코딩해야 합니다.

드라이버는 대상 프로세스를 내부에서 해석해야 합니다. 사용자 모드에서 PID를 받으면 안 됩니다. 프로세스 조회 방식은 전체 대상 이미지 이름을 지원해야 하며, 이름을 잘라서 제공하는 API만으로는 충분하지 않습니다.

드라이버는 플레이어 월드 위치를 읽는 데 필요한 좌표 체인을 하드코딩해야 합니다:
- 게임 모듈 베이스 해석 전략
- 월드 앵커 전략
- 플레이어 transform 체인
- world-origin 체인
- transform 및 origin 오프셋

드라이버는 이 하드코딩된 체인으로만 좌표를 반환해야 합니다. 임의 메모리를 읽거나 런타임 교체 오프셋을 받는 폴백 경로를 제공하면 안 됩니다.

참조된 모든 커널 프로세스 객체는 성공 및 실패 경로에서 항상 dereference되어야 합니다. 참조된 `PEPROCESS`는 사용자 모드로 반환되면 안 됩니다.

디바이스 객체는 제한적인 보안 설정으로 생성되어야 합니다. Administrators와 SYSTEM만 접근할 수 있어야 하며, 일반 사용자나 임의 로컬 프로세스는 접근할 수 없어야 합니다.

panic handler는 WumaTracker 전용 코드/태그를 사용해 `KeBugCheckEx`로 명시적으로 실패해야 합니다. 영원히 루프를 돌면 안 됩니다.

드라이버 바이너리는 일반 릴리스 stripping 이후에도 남고 표준 바이너리 검사 도구로 찾을 수 있는 목적 메타데이터를 포함해야 합니다. 메타데이터는 드라이버가 합법적인 WumaTracker 오버레이 서비스를 위해 플레이어 월드 좌표만 읽는다는 점을 명확히 밝혀야 합니다.

## 헬퍼 서비스 요구사항

헬퍼는 제한적인 파일시스템 및 서비스 ACL로 설치된 Windows 서비스 또는 상승된 헬퍼 프로세스로 실행되어야 합니다.

릴리스 빌드의 헬퍼 바이너리는 프로젝트의 프로덕션 서명 인증서로 Authenticode 서명되어야 합니다. 배포 환경에서 가능한 경우 EV 서명이 필요하지만, 서명만으로 드라이버 신뢰 경계가 완성되는 것은 아닙니다.

헬퍼는 시작 시 자신의 릴리스 서명을 검증하거나, 설치러/서비스 설정이 동등한 바이너리 무결성 보장을 제공해야 합니다. 선택한 보장 방식은 제출 패키지에 문서화해야 합니다.

정상 동작에서 드라이버 디바이스를 여는 컴포넌트는 헬퍼뿐이어야 합니다.

헬퍼는 명시적 보안 설명자가 있는 named pipe 또는 동등한 Windows IPC 메커니즘으로 로컬 IPC endpoint를 노출해야 합니다.

헬퍼 IPC ACL은 의도된 로컬 앱 identity와 Administrators만 허용해야 합니다. Everyone, Authenticated Users, 제한 없는 로컬 사용자 접근을 허용하면 안 됩니다.

헬퍼 IPC 계약은 현재 플레이어 위치 조회 한 가지 작업만 노출해야 합니다. raw IOCTL forwarding, 범용 메모리 읽기/쓰기, 패턴 스캔, 설정 가능한 포인터 체인, PID 선택을 노출하면 안 됩니다.

헬퍼는 다음 오류 상태를 명확히 반환해야 합니다:
- 헬퍼 미인가 또는 서명 검사 실패
- 드라이버 디바이스 사용 불가
- 대상 프로세스 없음
- 좌표 체인 읽기 실패
- 드라이버의 예상하지 못한 응답

## Tauri 앱 요구사항

Tauri 앱은 드라이버 디바이스를 직접 여는 대신 헬퍼 서비스와 통신해야 합니다.

앱에는 최종 상태에서 드라이버 IOCTL을 직접 호출하는 코드 경로가 없어야 합니다.

앱은 실행 상태와 사용자 표시 상태를 위해 user-mode 프로세스 확인을 계속 사용할 수 있지만, 그 확인 결과를 커널 메모리 읽기 설정에 사용하면 안 됩니다.

앱은 헬퍼와 드라이버 실패를 사용자가 조치할 수 있는 오류로 표시해야 하며, 드라이버를 통한 임의 user-mode 메모리 읽기 경로로 폴백하면 안 됩니다.

## 목적 메타데이터 요구사항

새로운 드라이버 관련 식별자, 주석, 바이너리 메타데이터, 제출 문구는 영어를 우선해야 합니다. 현지 검토자를 위한 짧은 한국어 문장은 선택적으로 포함할 수 있습니다.

바이너리 메타데이터는 다음을 포함해야 합니다:
- 제품/컴포넌트 이름
- 단일 목적 위치 텔레메트리 설명
- 쓰기 없음, 패턴 스캔 없음, 범용 메모리 접근 없음, 런타임 설정 없음에 대한 명시적 문구
- 프로젝트 또는 게시자 identity
- 버전 정보

Rust 문자열 리터럴을 메타데이터에 사용하는 경우 UTF-8 텍스트는 Rust에서 유효한 방식으로 표현해야 합니다. 한국어 텍스트를 `b"..."` byte string 안에 직접 넣으면 안 되며, 필요한 경우 명시적 byte escape를 사용해야 합니다.

## 검토 패키지 요구사항

제출 패키지는 다음을 포함해야 합니다:
- 목적 설명
- 아키텍처 요약
- 헬퍼 서비스 신뢰 및 바이너리 무결성 설명
- `IOCTL_GET_LOCATION` 하나만 표시하는 드라이버 IOCTL 목록
- 디바이스 SDDL 또는 동등한 보안 설명자
- 헬퍼 IPC 보안 설명자
- 대상 프로세스 이름 및 근거
- 좌표 체인 업데이트에는 새 서명된 드라이버 빌드가 필요하다는 설명
- Windows 10 22H2 및 Windows 11 23H2/24H2 테스트 매트릭스
- Driver Verifier 및 HLK 노트
- `strings` 또는 동등한 도구로 바이너리 목적 메타데이터가 확인된 증거

## 비기능 요구사항

별도 호환성 계획이 승인되지 않는 한 최종 구현은 x64 Windows 10+ 전용이어야 합니다.

드라이버는 큰 커널 스택 할당을 피해야 합니다. 약 1 KB를 넘는 버퍼는 nonpaged pool 또는 적절한 커널 할당 전략을 사용해야 합니다.

모든 커널 오류 경로는 명시적이고 진단 가능해야 합니다.

최종 ABI는 드라이버, 헬퍼, 앱이 서로 어긋나지 않도록 하나의 공유 기준에 문서화되어야 합니다.

게임 업데이트로 새 서명된 드라이버 빌드가 필요할 수 있다는 유지보수 비용은 수용합니다.
